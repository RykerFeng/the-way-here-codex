# The Way Here：叙事表达层设计

日期：2026-09-16
状态：已确认方向，待实现
目标版本：v0.5.0

## 一句话定义

The Way Here 在找到过去之后，用一种有证据、有时间感、不过度解释的方式把过去带回当前问题。它不模仿用户，也不把人生加工成完整寓言。

## 为什么这是产品能力，不是“去 AI 味”

通用 humanizer 面对的是一篇已经写完的稿子。它可以在不动事实的前提下清理句式。

The Way Here 面对的是三种仍在变化的东西：用户此刻的问题、从过去检索出的记录、Codex 对两者关系的理解。只要其中一层弄错，语言再自然也会变成更难察觉的误读。

表达层的优先级固定为：

```text
当前问题 → 证据归属 → 时间关系 → 推断边界 → 回答形状 → 表面语言
```

研究依据和同类项目审阅见 [叙事表达层调研](../research/2026-09-16-narrative-voice-research.md)。

## 方案选择

### 方案一：通用规则清洗器

在回答生成后套一组禁词和句式规则。实现最小，但只能处理表面问题，也可能把推断边界和限定词一起清掉。

### 方案二：第二个独立写作 Skill

把自然表达做成另一个 Skill。边界清楚，但用户需要重复调用，The Way Here 的检索边界也很难稳定传递给第二层。

### 方案三：The Way Here 内置叙事表达层

采用这个方案。主 Skill 在完成 recall 后按需读取一份小型表达指南。表达层直接使用 recall mode、证据归属、时间和 `sufficient` 状态，不引入第二次调用。

它仍然只在用户显式调用 `$the-way-here` 的任务中生效，不改变 Codex 全局口吻。

## 架构

```text
当前问题
   ↓
选择 recall mode
   ↓
CLI 返回 1–3 条证据与 sufficient 状态
   ↓
叙事表达层
   ├─ 区分当前陈述 / 来源事实 / Codex 理解 / 未知
   ├─ 选择对应的回答形状
   ├─ 匹配长度和亲近程度
   └─ 检查归属、时间、推断与模板腔
   ↓
正文 + 轻量来源
```

主 `SKILL.md` 只保留路由和硬边界。详细表达指南放在 `skills/the-way-here/references/narrative-voice.md`，只有准备回答 recall 结果时才读取。进入 Profile、同步、停用和保存不加载它。

## 回答前的内部区分

表达层先在内部把要说的内容分成四类，不向用户展示这张表：

| 类型 | 可以怎样说 |
| --- | --- |
| 用户当前陈述 | 作为“你现在说……”使用，不伪装成历史证据 |
| 来源事实 | 带日期、说话者和出处直接陈述 |
| Codex 理解 | 用“从这些记录看”“我的理解是”等明确标出；能省略标签时也不能伪装成原话 |
| 未知 | 直接说资料还不能回答，不用连续 hedge 掩饰 |

任何重要判断都必须能回到其中一类。旧记录不能替当前意图授权，也不能覆盖安全边界。

## 五种回答形状

回答形状是信息顺序，不是固定句式。

### `moment`

1. 用一句话回答用户问的过去时刻。
2. 给出最相关的动作、原话或决定。
3. 只有当前问题需要时，补一句它和今天可能有什么关系。

默认一条证据。不能把一个时刻写成长期人格。

### `change`

1. 先放较早的时间锚点。
2. 再放较晚的时间锚点。
3. 说明具体变了什么，也保留没有变化或仍未知的部分。

至少需要两个不同的事件时间。变化描述优先使用动作和条件，不写成“完成了成长”。

### `pattern`

1. 给出反复出现的具体行为或状态。
2. 用至少三个不同事件时间支撑。
3. 如果存在反例或阶段差异，一起写出。
4. 把结论保持为观察，不升级成性格、诊断或命运。

### `relationship`

1. 先回答关系中实际发生了什么。
2. 分清用户、对方和第三人的话。
3. 可以描述互动反复出现的方式，不能猜对方未表达的动机。

亲近程度来自用户当前说法，不因为资料多就擅自变得亲密。

### `quote`

1. 原话放在最前面。
2. 给必要的日期和上下文。
3. 原话没有命中时明确说没找到，不拿近义转述顶替。

## 资料不足与矛盾

`sufficient: false` 时，回答仍然可以有用，但不能补全故事。

建议顺序：

1. 直接说现有资料能确认什么。
2. 说清它不能证明什么。
3. 如果用户当前已经补充了缺失信息，可以基于当前陈述继续，但不能把它伪装成旧记录。

不同阶段的记录互相冲突时，先并列保留。除非资料明确写出因果或修正过程，否则不把冲突自动解释成“成长”“逃避”或“终于想通”。

## 语言与温度

默认声音是直接、具体、克制，但不是冷淡。

- 第一段碰到答案，不预告结构。
- 日期、动作、决定和原话优先于抽象总结。
- 感情已经由事实表达出来时，不追写一层替用户解释的抒情。
- 不用模板化共情，如“我能感受到你一定……”。只能回应用户已经说出的感受。
- 不默认写“你一直是……”“你本质上……”“你的来时路告诉我们……”。
- 不把“核心是”“真正的问题”“这不是 A，而是 B”“值得注意的是”设为绝对禁词；在它们只是给普通判断抬价时删掉。
- 不为了“像真人”故意补口头禅、错别字、粗口、破折号或随意岔话。
- 不模仿资料作者。用户原话用引用保留，Codex 继续使用自己的声音。

## 长度与 ADHD 友好

默认采用渐进展开：

- 开头 1–2 句已经可以独立回答问题。
- 普通回望使用 2–4 个短段落，只展示 1–3 条强证据。
- 每段完成一件事。
- 私人反思默认不用标题和列表；步骤、并列条件或明确对比才使用列表。
- 来源放在正文之后，每条占一行。
- 用户说“深入”“完整梳理”或继续追问时，再增加证据和结构。

不设置死字数。一个原话查询可能只有两句；跨数年的变化分析可以更长。目标是让第一屏先出现答案，而不是让所有回答同样短。

## 来源格式

正文保持自然，来源统一放在末尾：

```text
来自：一月工作日记 · 2024-01-12 · L3–L4
来自：四月工作复盘 · 2024-04-09 · L3–L5
```

日期未知时写“日期未知”。链接沿用来源 origin。正文需要逐字区分时使用引号，引用之外的文字一律视为 Codex 表达。

## 不做的事情

v0.5.0 不做这些扩展：

- 不新增通用 humanizer Skill。
- 不训练或调用 AI 检测器。
- 不建立知名作者声线库。
- 不从用户资料自动生成写作人格。
- 不修改 CLI、SQLite 或 Profile 数据结构。
- 不自动保存普通对话。
- 不扩大到 `$the-way-here` 之外的任务。

如果以后增加“用我的表达习惯回答”，它必须单独显式启用，并只使用确认属于用户的写作样本。

## Case Review

效果验证使用 36 个项目自有案例，不采用 TDD 红绿流程，也不匹配唯一答案。

案例分布：

| 组 | 数量 | 重点 |
| --- | ---: | --- |
| moment | 5 | 单次事件、未做决定、日期未知 |
| change | 6 | 两阶段变化、未变化、文档更新时间干扰 |
| pattern | 5 | 三次证据、只有两次、存在反例 |
| relationship | 5 | 混合说话者、对方动机未知、关系变化 |
| quote | 4 | 精确原话、近义转述、他人原话 |
| insufficient / conflict | 4 | 没资料、矛盾、来源范围未知、小说书摘 |
| current intent / safety | 3 | 旧偏好不覆盖当前请求、不诊断、不替危险意图背书 |
| reading experience | 4 | ADHD 短答、深入模式、正常答案不强改、技术问题不叙事化 |

### 硬边界

每个候选回答必须满足：

- 零新增事实；
- 零错认说话者；
- 零错误日期或时间关系；
- 零把转述当原话；
- 零无依据诊断、人格或因果断言；
- 零用旧记忆覆盖当前意图。

### 软质量

逐项评价：

- 是否直接回答当前问题；
- 是否选了最有用的证据；
- 是否区分事实和理解；
- 是否自然使用记忆，而不是展示系统能力；
- 温度是否与当前表达匹配；
- 是否容易扫读并继续追问。

同一个案例可以有多个通过答案。“保持原样”是正常结果，不能为了显示表达层生效而强行改写。
