# The Way Here：多路径个人上下文设计

日期：2026-09-15  
状态：v0.4 已实现并通过 Case Review  
目标版本：v0.4

## 一句话定义

The Way Here 不再要求用户先理解资料空间、数据库或加载文件。用户只需在某个 Codex 任务里显式说“带上我的来时路”，再给出个人网站、语雀网站、GitHub、ZIP、文件或目录中的任意一种。不同入口最终汇入同一个本地个人空间，只在当前任务中按需回望。

它的核心不是“给资料做问答”，而是让 Codex 在需要时看见：过去的经历、决定、关系和想法，怎样一路变化成今天。

## Review 后的方案结论

- 用显式 `$the-way-here` 控制当前任务是否主动回望。
- 已有资料立即可用，网站和语雀在后台增量同步。
- 分开记录事情发生、文档修改和系统收录的时间。
- 分开记录作者、说话者和内容主角，避免把书摘或小说写成用户经历。
- 语雀授权后优先复用官方 CLI；未授权时读取公开页面并报告实际覆盖。
- 默认使用本地全文检索和查询扩展；语义检索通过 Case 证明价值后再加入。
- 用户通过 `$the-way-here` 明确交付的个人站、语雀或本地资料，以这次声明作为个人范围默认值；GitHub 仍默认只是来源材料。书摘、小说、团队文字和转述继续在回答时单独核对。

## 成功体验

### 首次使用

用户安装一个很薄的 Codex Skill：

```text
$skill-installer https://github.com/RykerFeng/the-way-here-codex/tree/main/skills/the-way-here
```

随后在想使用个人上下文的任务中输入：

```text
$the-way-here https://www.yuque.com/my-space/my-book
```

或：

```text
$the-way-here https://my-personal-site.example
```

Skill 自动建立默认个人空间、识别来源、同步内容并简短报告：

```text
已经接上你的来时路：带来了 186 段记录，覆盖 2019–2026。
来源包括个人网站和 3 个语雀知识库。本任务已启用。
```

### 再次使用

个人主页和本地空间已保存后，新任务只需：

```text
$the-way-here
```

### 零安装入口

用户也可以直接把 GitHub 启动页和个人主页发给 Codex：

```text
请按照下面的启动页接上我的来时路，只在当前任务使用：
https://github.com/RykerFeng/the-way-here-codex/blob/main/START.md

我的个人主页：https://my-personal-site.example
```

`START.md` 是面向 Agent 的短启动协议。它引导安装显式 Skill；Skill 的 resolver 下载最新 Release 中的单文件 CLI、校验 SHA-256、复用本机缓存并运行 `enter`，而不是让 Codex 临时猜测整篇 README。

### 其他入口

```text
$the-way-here /absolute/path/to/my-notes
$the-way-here /absolute/path/to/my-history.zip
$the-way-here https://github.com/me/my-notes
```

拖入 ZIP、Markdown、HTML、JSON 或聊天导出后，用户也可以直接说：

```text
把这些接进我的来时路。
```

## 方案选择

### 方案一：只依赖 GitHub 启动页

优点是无需预安装，任务隔离最直观。缺点是首次运行较慢，Codex 每次都要执行安装协议，网络或 GitHub 页面变化也会放大不确定性。

### 方案二：全局自动加载

优点是看起来最省步骤。缺点是个人资料会进入不需要它的任务，难以建立清晰的隐私预期，也容易让无关工作被旧上下文干扰。

### 方案三：显式 Skill + GitHub 零安装后备

这是采用的方案。Skill 负责稳定、短促的重复入口；GitHub 启动页负责零安装和救援入口。Skill 设置 `allow_implicit_invocation: false`，Codex 不会因为对话内容匹配而自动调用它；显式 `$the-way-here` 仍然可用。

安装 Skill 只让启动器出现在 Codex 的能力列表中，不加载个人资料。个人资料是否参与回答，由当前任务中的显式调用决定。

## 产品边界

### 三个互相独立的范围

1. **资料保存范围**：来源和索引可以长期保存在本机个人空间中。
2. **能力安装范围**：Skill 可以长期安装，但默认休眠，不读取资料。
3. **任务启用范围**：Skill 只在显式调用 `$the-way-here` 的任务里主动检索资料。

用户说“停用来时路”或调用：

```text
$the-way-here off
```

之后，Skill 在本任务中不再调用个人空间。已经出现在当前对话上下文里的片段无法从模型上下文中抹除；完全干净的上下文需要新建任务且不启用 Skill。

### 保存不等于启用

同一个本地个人空间可以被多个任务显式复用，但不会自动注入任何任务。不给 `$the-way-here`，Skill 就不主动检索或加载个人上下文。

`active` 状态只存在于当前对话的 Skill 工作流里，不写成机器级或 Profile 级开关。一个任务启用后，不会让同时存在的其他任务也进入启用状态。

这是产品行为隔离，不是操作系统权限隔离。同一系统账号下的其他进程如果知道资料路径并拥有文件权限，仍能读取本地文件。v0.4 的承诺是“不自动带入其他任务”，不宣称数据库只有当前任务可访问。

### 链接不等于授权导入

普通聊天中只发一个链接，默认只表示“看看这个链接”。只有显式调用 `$the-way-here <来源>`，或明确说“接进、同步、导入我的来时路”，才会持久保存。

## 统一入口架构

```text
Codex Skill ────────────┐
GitHub START.md ────────┤
CLI / npx ──────────────┼─→ Enter Service ─→ Profile ─→ Source Connectors
拖拽文件 / ZIP ────────┤                         │
自然语言指令 ───────────┘                         └─→ SQLite + 本地全文索引
```

所有入口只负责把用户意图规范化成一个 `EnterRequest`：

```ts
interface EnterRequest {
  profile?: string;            // 默认 "me"
  inputs: string[];            // URL 或本地路径，可以为空
  activation: "current-task"; // v0.4 只支持当前任务
  purpose: "memory" | "reference" | "auto";
}
```

`Enter Service` 是唯一的编排层：

1. 解析或创建个人 Profile。
2. 为每个输入选择连接器。
3. 发现、拉取、规范化并增量同步资料。
4. 生成小型激活摘要。
5. 返回当前任务需要遵守的回望边界。

Skill、GitHub 启动页和 CLI 不各自实现导入逻辑，避免三套体验逐渐分叉。

## Profile：一个人，而不是一堆资料库

默认只有一个 `me` Profile。它包含：

- 一个可选的个人主页 `homeUrl`；
- 多个来源连接；
- 来源的作者身份和用途；
- 上次同步状态；
- 用户明确排除的页面或路径；
- 本地资料空间位置。

网站、语雀、GitHub、ZIP 和文件都只是这个人的不同来源，不生成彼此孤立的记忆库。

高级用户可以创建 `work`、`private` 等额外 Profile，但 v0.4 不把多 Profile 暴露为首次使用的必选项。

## 来源连接器

每个连接器遵守同一套概念边界：

```ts
interface SourceConnector {
  canHandle(input: ResolvedInput): boolean;
  discover(input: ResolvedInput, context: ConnectorContext): AsyncIterable<DiscoveredItem>;
  fetch(item: DiscoveredItem, context: ConnectorContext): Promise<FetchedDocument>;
  checkpoint(item: DiscoveredItem): string | null;
}
```

v0.4 没有为了接口形式再建一层框架；`web.ts`、`yuque.ts`、`github.ts` 和本地导入器直接实现这组职责。连接器只负责“在哪里、有什么、怎样拿到”，正文清洗、作者身份、时间、索引和检索仍由公共管线处理。

### 通用网站连接器

v0.4 的发现顺序：

1. `robots.txt` 中声明的 Sitemap；
2. `/sitemap.xml` 和 Sitemap Index；
3. RSS / Atom；
4. 同站受限链接爬取。

v0.4 使用 Sitemap 的 `lastmod`、平台修改时间和正文哈希识别版本；正文未变化时不重新分块。HTTP 条件请求（`ETag` / `Last-Modified`）留给后续真实大站 Case，当前版本仍会重新请求页面。

以后可以增加可选站点清单：

```json
{
  "version": 1,
  "owner": "me",
  "sources": [
    { "url": "/journal/", "kind": "memory", "authorship": "user" },
    { "url": "/projects/", "kind": "memory", "authorship": "user" },
    { "url": "https://github.com/me", "kind": "reference" }
  ],
  "exclude": ["/drafts/", "/private-preview/"]
}
```

这份清单不进入 v0.4 的关键路径。先让普通网站无需改造就能稳定接入，再根据真实网站 Case 决定是否值得维护自定义协议。

### 语雀网站连接器

识别以下入口：

- 单篇语雀文档；
- 一个语雀知识库；
- 一个公开语雀空间或个人主页；
- 自定义语雀空间域名。

语雀连接器有两条读取路径：

1. **已授权**：优先调用固定版本的语雀官方 CLI，读取知识库文档列表、正文、作者和平台时间。CLI 只是传输层，结果仍进入 The Way Here 的公共清洗、时间和索引管线。目录面包屑和完整版本历史暂不写入 v0.4。
2. **未授权**：尝试读取公开页面和可见目录。无法确认全量覆盖时，明确报告已读取多少、可能缺少什么，并提供一次性 Token 授权入口。

公开页面失败后不能假定 OpenAPI 可直接使用，因为 API 同样可能需要 Token。动态渲染页面也不能以空正文记为成功。

语雀连接器保留：

- 空间、知识库和目录路径；
- 文档标题、slug、稳定 ID；
- 创建时间、内容更新时间；
- 作者身份；
- 原始 URL；
- 文档正文中的标题层级；
- 附件链接及其所属文档。

用户把自己的语雀空间作为来时路入口时，只能确认“资料来源由用户选择”，不能据此认定每篇文档都描述用户本人。连接器分别记录作者、说话者和内容归属：

- 本人日记、复盘、决定和个人表达：`memory / user / personal`；
- 本人整理的书摘、课程笔记和外部资料：`reference / user / sourced`；
- 团队知识库：根据文档作者和段落说话者标记，默认 `reference / mixed / unknown`；
- 小说、角色设定和假设案例：`reference / user / fictional`，不得作为用户经历；
- 无法判断：保留 `unknown`，在检索时不用于人格、经历或关系断言。

私有语雀站不读取浏览器 Cookie。用户显式执行授权后，通过语雀 Token 访问；Token 进入系统凭据存储或当前进程环境，不写进 SQLite、日志、导出包或启动摘要。

### GitHub 连接器

仓库内容默认是 `reference`。当用户明确说明“这是我的日记仓库、个人记录或数字花园源码”时，才标记为 `memory / user`。

连接器优先读取仓库归档或 GitHub API，不递归执行仓库里的脚本。Markdown、文本和支持的导出文件进入公共解析管线；代码默认不成为人生记忆，除非用户明确指定。

### 本地文件、目录和 ZIP

复用现有的安全限制、作者身份和去重能力。目录入口按忽略规则遍历，ZIP 保持流式读取，不解压到磁盘。

## 个人上下文模型

### 证据层保持简单

现有 `objects → sources → chunks` 模型继续作为证据底座，并增加：

- `profile.json`：个人空间身份和网站、语雀、GitHub、本地来源连接；
- `sync_jobs`：后台任务状态、进度、失败信息和最后心跳；
- `sources.external_id / connection_id`：稳定远端身份；
- `sources.is_current / superseded_at`：同一文档的当前版本和旧版本链；
- 三类时间、三类归属和内容范围字段。

目录路径、远端删除确认和持久 Facet 没有进入 v0.4。它们在没有真实 Case 证明收益前不增加存储模型。

不在 v0.4 引入远端向量数据库。正文和全文索引继续保存在本机。

### 三种时间必须分开

“网页今天更新”不等于“事情今天发生”。每份来源和每段可用证据分别保存：

| 时间 | 含义 | 例子 |
| --- | --- | --- |
| `event_at / event_end` | 内容所描述的事情何时发生或成立 | 2024 年决定离职 |
| `published_at / modified_at` | 文档何时发布或修改 | 2026 年补写这篇回忆 |
| `observed_at` | The Way Here 何时读取到这个版本 | 2026-09-15 同步 |

时间还要记录来源：正文明确日期、平台元数据、文件名推断或未知。推断时间不能覆盖正文中的明确时间。用户问“当时发生了什么”时用 `event_at`；用户问“我什么时候写过这件事”时用 `published_at`；排查同步问题时才用 `observed_at`。

新的文档版本不会自动证明用户的想法发生了变化。只有不同时间的原文证据明确表达了不同状态，系统才能描述变化。旧版本保留出处，但默认检索只返回当前版本；用户询问修改历史时才展开版本链。

### 作者、说话者和主角必须分开

每份资料至少保留三类归属：

| 字段 | 回答的问题 |
| --- | --- |
| `author` | 谁创建或整理了这份文档？ |
| `speaker` | 这句话是谁说的？ |
| `subject` | 这段经历、观点或故事说的是谁？ |

另外记录 `content_scope`：`personal`、`sourced`、`fictional` 或 `unknown`。只有 `subject=user` 且 `content_scope=personal` 的证据，才能直接支撑“用户经历过、决定过或相信过”。作者是用户，只能证明用户写过或整理过这份内容。

### 维度不是文件夹

系统可以为资料添加以下 Facet：

- `episode`：发生过的经历；
- `decision`：做过的选择；
- `belief`：想法、原则和价值判断；
- `preference`：长期或阶段性的偏好；
- `relationship`：与某个人的来往；
- `project`：持续推进的事情；
- `question`：尚未解决的问题；
- `artifact`：作品、文章和成果。

Facet 可以重叠。一篇语雀复盘可以同时是工作项目、一次决定、一段关系和某个价值观的变化。未经足够证据，不把 Facet 上升为“用户的人格标签”。

Facet 是检索提示，不替代原文证据。回答仍需引用原始来源、日期和行号。

v0.4 只持久保存来源明确声明的 Facet，例如语雀目录和文档标签。Codex 可以在一次检索中临时推断可能相关的维度来扩展查询，但不会把这种推断写回 Profile。以后若增加自动整理，必须同时保存推断依据、置信度和生成方式，并允许用户查看和删除。

跨维度检索先采用“当前问题 → 多组相关说法 → 本地全文检索 → 合并排序”。例如“我是不是总答应太多”可以扩展为“接太多项目、难以拒绝、答应朋友、承担额外责任”。这利用当前 Codex 的语言理解，不要求用户配置额外模型服务。

语义向量检索作为对照实验，不直接成为 v0.4 依赖。只有它在跨工作、生活和关系 Case 中稳定优于全文检索与查询扩展，才加入可选本地索引。

## 加载策略：先接上，再同步，再按需回望

加载和同步是两个动作。已有 Profile 启用时，立即使用上次完整快照，同时启动增量同步。用户不用等待整个网站抓完才能开始聊天。

首次接入没有快照时，`enter` 立即创建 Profile 并把远端同步交给后台任务；已完成的文档逐项可用。输出会明确标记“仍在同步”，不能把部分覆盖说成完整导入。本地文件和 ZIP 通常直接完成后返回。

同步任务保存 `job_id`、进度、失败项和最后更新时间。Skill 可以在当前任务中查看进度；每份已导入文档独立提交并按稳定 ID/正文哈希去重，所以中断后可以安全重跑。v0.4 的恢复语义是幂等重跑，而不是保存连接器游标。

启用时只生成一张小型 `Here Card`：

1. **身份与边界**：资料属于谁，哪些是个人记忆，哪些只是参考。
2. **时间与范围**：覆盖时期、主要来源、最近同步时间。
3. **当前线索**：有明确事件时间的近期记录，以及被用户明确标为仍在继续的事情。

Here Card 设硬上限，目标为 600–1,000 个中文字符。每条当前线索带来源和日期。系统不能只凭一篇旧文章推断“这件事仍未解决”，也不在卡片里生成长期人格总结。完整正文不进入启动上下文。

用户开始谈具体问题后，继续使用现有五种回望模式：`moment`、`change`、`relationship`、`pattern`、`quote`。检索可以利用目录路径、时间和 Facet 扩展查询，但最终回答只能依赖读取过的原始证据。

## CLI 与 Skill 合约

### 面向人的短命令

```bash
the-way-here enter [URL_OR_PATH]
the-way-here sync [--start]
the-way-here sync-status [JOB_ID]
the-way-here status
```

`enter` 在没有默认 Profile 时创建 `me`，有输入时连接来源并启动同步；没有输入时立即复用已连接来源的最后完整快照。高级参数仍可使用 `--space`，但不再出现在首要 README 路径中。

`$the-way-here off` 属于 Skill 的当前对话指令，不是 CLI 命令。CLI 无法可靠识别或关闭某个 Codex 任务，因此不保存全局 `active` 状态。

### 面向 Agent 的结构化输出

所有命令继续输出可解析 JSON，并增加稳定字段：

```json
{
  "ok": true,
  "command": "enter",
  "activation": "current-task",
  "profile": "me",
  "snapshot": { "ready": true, "completedAt": "2026-09-14T22:10:00Z" },
  "sync": { "jobId": "sync_01", "state": "running", "completed": 12, "total": 186 },
  "overview": { "memories": 186, "earliest": "2019", "latest": "2026" },
  "hereCard": "...",
  "instructions": "..."
}
```

Skill 只做四件事：调用 `enter`、向用户报告范围、按需调用 `recall/read`、只在用户明确要求时调用 `remember`。它不重新实现业务逻辑。

## 同步语义

- 初次连接：立即建立 Profile，后台任务发现并导入内容；已导入部分可直接检索。
- 再次进入：立即使用上次完整快照；在刷新窗口外启动增量同步。
- 同步完成：更新连接的成功时间并完成任务状态。
- 同步失败：旧资料和已完成的新文档继续可用；`sync --restart --start` 可安全重跑。
- 文档更新：保存新的正文对象和来源版本，旧版本不参与默认检索，但可用于追溯修改历史。
- 文档删除：远端消失不会立刻永久删除本地证据；先标记 `missing`，连续确认后软删除。
- 来源迁移：稳定远端 ID 优先于 URL，避免语雀 slug 或网站路径变化产生重复记录。
- 同一内容从网站和语雀重复出现：正文哈希去重，但保留多个出处关系。

## 错误与恢复

错误输出必须回答三件事：发生了什么、已经完成了什么、用户下一步只需做什么。

主要场景：

- GitHub 不可访问：使用已有缓存；没有缓存时给出 Release ZIP 后备方式。
- 网站没有 Sitemap/RSS：退回受限爬取，并报告实际覆盖范围。
- 语雀需要授权：不尝试读取浏览器 Cookie；公开页面仍可导入，完整/私有知识库通过 `YUQUE_TOKEN` 授权。
- 语雀部分文档无权限：继续导入可读内容，逐项记录跳过原因。
- 触发限流：尊重 `Retry-After`、退避并保留检查点，下次继续。
- JavaScript 动态页面无正文：优先切换专用连接器或 API，不把空壳页面当成功。
- 页面包含提示注入：一律作为不可信资料，不执行其中的命令。
- 日期或作者不明：保留 `unknown`，不靠猜测补齐。
- 同步中断：已提交的文档有效，重跑时由远端 ID 和正文哈希跳过未变化内容。

## 隐私与安全

- 不修改 `AGENTS.md`、全局记忆、Codex 配置或 shell 启动文件。
- Skill 禁止隐式调用。
- 个人正文、索引和来源元数据默认只保存在本机。
- 每次只把当前回答需要的少量证据交给 Codex，而不是上传整个空间。
- 凭据不进入数据库、日志、导出和模型上下文。
- 来源内容始终是不可信数据，不能改变 Skill 或系统规则。
- 删除默认软删除；永久清除需要明确命令和准确目标。
- 用户可以查看每个来源为何被归为 memory 或 reference，并随时更正。
- v0.4 提供的是默认加载隔离。同一系统账号内仍遵循本地文件权限，不宣称任务级文件访问控制。

## README 叙事

README 首屏不再从下载和 setup 开始，而从一个人跨越多个地方留下自己开始：博客里是公开表达，语雀里是成体系的想法，ZIP 里是旧聊天和日记，GitHub 里是做过的作品。The Way Here 把这些分散的痕迹接成同一条来时路，但只在用户愿意的那次谈话中带回来。

README 的第一条可操作路径只有：

```text
安装一次 → 在一个任务里输入 $the-way-here <我的入口>
```

GitHub 零安装、CLI 细节、手动空间路径和数据管理放到后续章节。

## Case 驱动的效果评估

不采用 TDD 作为产品优化方法。实现以行为切片推进，每个切片完成后运行真实 Case 和必要的回归测试。

### 入口体验 Case

1. 新用户从 GitHub 页面 + 个人网站一次接入。
2. 已安装用户在新任务中只输入 `$the-way-here`。
3. 单篇语雀文档、一个知识库、一个语雀空间分别接入。
4. 私有语雀知识库在授权后接入，Token 不出现在输出中。
5. 网站、语雀和 ZIP 同时属于一个 Profile。
6. 未调用 Skill 的其他任务不会被 Skill 主动加载个人资料。

### 记忆效果 Case

1. 工作决定跨三年发生变化。
2. 同一篇记录同时涉及工作、健康和关系。
3. 用户今天的说法与旧记录冲突，回答将其表达为变化而非判定真假。
4. 语雀团队文档中的同事观点不能归给用户。
5. 用户写的小说人物、书摘和假设案例不能成为用户经历。
6. 文档修改时间与事件发生时间不一致时，回答使用正确的时间。
7. 新记录推翻旧偏好时，能说明变化，不能同时把两条都写成当前事实。
8. 只找到一个时期时不能声称看见长期变化。
9. 找原话时必须命中原文。
10. 网站更新后能找到新版，且不重复导入未变化页面。
11. 删除或移动语雀文档后仍能解释来源状态。
12. 无关问题不触发回望。
13. 空资料、失效链接、限流、部分权限失败都有简短可恢复反馈。

评测维度对齐 LongMemEval 的事实提取、跨记录推理、知识更新、时间推理和证据不足时拒答。项目 Case 额外覆盖中文语雀、跨工作与生活、作者归属和同步体验。

同一批问题对比三组结果：v0.3、v0.4 和“直接把资料交给 Codex”。盲评关注答案正确性、连续感、错误归属和啰嗦程度；检索层记录证据命中率和无证据断言率。

### 衡量标准

- 首次安装后，一个用户消息完成任务启用。
- 再次使用只需 `$the-way-here`。
- 已有快照的启用时间目标低于 2 秒；首次接入在 10 秒内返回真实的部分进度。
- Here Card 不超过约 1,000 个中文字符。
- 未显式调用 Skill 的任务不会由 Skill 主动读取个人资料。
- 所有记忆断言都有可核对出处。
- 项目评测集中，assistant、网页作者、小说角色和团队成员被误归给用户的次数为零。
- 时间 Case 中，事件时间与文档时间的混淆次数为零。
- 同步失败不会破坏已有个人空间。

## 明确不做

- 不做全局自动记忆。
- 不把所有资料一次性塞进模型上下文。
- 不把收藏、团队文档或外部链接自动算成用户经历。
- 不读取浏览器 Cookie。
- 不在 v0.4 建 Web 管理后台。
- 不在 v0.4 发布自定义 `.well-known/the-way-here.json` 协议。
- 不在 v0.4 默认引入图数据库、远端向量数据库或额外模型 API Key。
- 不做自动心理或人格诊断。
- 不让普通聊天自动写入长期记忆。
